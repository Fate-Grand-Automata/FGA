# GitHub workflows

`.github/workflows/actions.lock` pins every `uses:` reference of every workflow to a commit. It
is generated by the [`gh actions-lock`](https://github.com/github/gh-actions-lock) extension and
never edited by hand.

Any change to a workflow file — adding, removing or renaming a workflow, or adding, removing or
changing a `uses:` line — must be committed together with a regenerated lockfile:

```bash
gh extension install github/gh-actions-lock   # once
gh actions-lock                               # rewrite the lockfile from .github/workflows/
gh actions-lock --verify                      # confirm every reference is locked
```

Run `gh actions-lock` without path arguments so entries for deleted or renamed workflows are
pruned. A workflow or action missing from the lockfile is blocked from running by the repository's
*Require lockfile* policy.

Workflows that use a same-repo `./…` action cannot be locked; reference it as `$/…` instead.

Renovate bumps action versions and updates the lockfile in the same PR.
